v2.0.0 · VERCEL + WINDOWS RDP

CMS online.
Mesin loop tetap di RDP.

Kontrol dari HP/PC: daftar judul, interval, Start/Pause, Ganti sekarang, dan status. Satu video/live tetap jalan, judul berulang dari awal setelah antrean terakhir.

Paket ini belum di-deploy ke akun lo. Pasang database + CMS dahulu, lalu hubungkan agent RDP. Token YouTube tetap disimpan di Windows RDP.

1. Siapkan database Supabase

  1. Buat project khusus tool ini di Supabase.
  2. SQL Editor → New query. Buka cms/supabase.sql, salin seluruh isinya dan Run sekali.
  3. Ambil Project URL dari Connect/project settings. Di Settings → API Keys ambil secret key sb_secret_.... Key ini hanya dipasang sebagai environment variable Vercel.

Script bisa diulang tanpa menghapus data. Tidak perlu membuat akun user di Supabase Auth; CMS punya password owner sendiri.

2. Upload project CMS ke GitHub

Buat repository baru lalu upload isi folder cms ke root repository: folder api, lib, public, serta package.json, vercel.json dan file project lainnya.

Kalau lo upload seluruh paket (cms + rdp), nanti di Vercel pilih Root Directory = cms. Jangan upload token, file credentials Windows, atau .env berisi secret.

3. Import ke Vercel

  1. Buka Vercel → Add New Project, pilih repository tadi.
  2. Framework Preset Other. Node.js 22.x. Output Directory public. Tidak perlu build command.
  3. Isi 6 Environment Variables untuk Production sesuai tabel di bawah.
  4. Deploy. Periksa URL production final. Jika berbeda dari CMS_PUBLIC_URL, ubah environment variable itu lalu Redeploy.
NamaIsi
SUPABASE_URLURL project Supabase
SUPABASE_SECRET_KEYSecret key sb_secret_... dari Supabase; backend saja
CMS_PASSWORDPassword login CMS, minimal 12 karakter
SESSION_SECRETNilai acak minimal 32 karakter
AGENT_KEYNilai acak berbeda minimal 32 karakter
CMS_PUBLIC_URLOrigin production final, contoh https://nama.vercel.app

Jalankan GENERATE_KEYS.bat di perangkat sendiri untuk membuat password/secret acak. Simpan hasil secara pribadi. Jangan membagikannya di chat/GitHub. Tidak ada secret production bawaan paket.

Jika Vercel Authentication menahan akses API agent dengan 401/redirect, periksa metode akses machine resmi/proteksi production akun lo. Tool tidak mengubah proteksi Vercel secara otomatis.

4. Pasang agent di Windows RDP

  1. Jika versi v1 masih jalan, buka dashboard v1 → Pengaturan → Tutup program.
  2. Simpan folder rdp v2 di lokasi tetap, misalnya C:\Tools\YouTubeLoopRDP.
  3. Install Python 3.10+ bila belum ada, centang Add Python to PATH. Tidak perlu pip/package tambahan.
  4. Double-click rdp/START.bat. Dashboard lokal terbuka di http://127.0.0.1:8765 dalam browser RDP.
  5. Hubungkan YouTube. Jika token v1 tersimpan pada user Windows yang sama, koneksi dapat digunakan lagi.

Setup Google pertama kali: Google Cloud → aktifkan YouTube Data API v3 → Google Auth Platform → isi Branding/Audience/Test user → scope https://www.googleapis.com/auth/youtube.force-ssl → Clients Desktop app → download JSON. Import JSON lewat Pengaturan agent, lalu Hubungkan YouTube dan buka link login Google di browser RDP.

External Testing untuk scope YouTube umumnya memakai refresh token 7 hari. Untuk jangka panjang periksa In production/verifikasi Google; jika token dicabut/kedaluwarsa, hubungkan ulang.

5. Pair RDP ke CMS

  1. Di dashboard lokal RDP → Pengaturan → Hubungkan CMS Vercel.
  2. Masukkan URL production CMS dan AGENT_KEY yang sama persis dengan Vercel.
  3. Klik Hubungkan CMS. Pairing menjeda loop lokal.
  4. Buka CMS di HP/PC, login memakai CMS_PASSWORD. Tunggu badge RDP ONLINE.
  5. Mulai video streaming melalui aplikasi yang biasa lo gunakan di RDP.
  6. Di CMS: Refresh live → tunggu perintah Selesai → pilih live aktif.
  7. Isi satu judul per baris dan interval menit → Simpan antrean → tunggu Selesai → Start Loop.

Start pertama langsung memakai judul pertama. Setelah interval, lanjut judul berikutnya; setelah terakhir kembali ke awal.

Kontrol harian

TombolHasil
Pause LoopJudul berhenti berganti, video tetap live.
Ganti sekarangMaju satu judul. Tidak memutus video.
Reset ke judul pertamaSaat pause: reset posisi. Start berikutnya memakai judul pertama.
Stop Live YouTubeAkhiri sesi YouTube dan pause loop. Encoder tetap berjalan.

Normalnya perintah diterima pada sync berikutnya (sekitar 15 detik); koneksi/API yang lambat bisa menambah waktu. Tersimpan belum berarti sudah dieksekusi—lihat status Selesai/Gagal.

Jika CMS/internet sync tidak terjangkau, agent memakai jadwal terakhir. Pause di CMS belum berlaku sampai RDP menerima perintah. Darurat di RDP: Pengaturan → Putus CMS + pause.

Background dan autostart

Setelah setup, tutup program lewat Pengaturan, lalu double-click RUN_BACKGROUND.vbs agar berjalan tanpa CMD. Tab CMS/dashboard lokal boleh ditutup. Agent dan encoder harus tetap hidup.

Aktifkan autostart di Pengaturan lokal. Berlaku saat user Windows login, bukan sebelum login. Jangan memindahkan folder aplikasi setelah aktif.

Disconnect RDP boleh jika provider membiarkan sesi hidup. Sign out, reboot, sleep atau session timeout provider dapat menghentikan agent dan video. Tool tidak menyalakan encoder setelah reboot.

Kalau belum jalan

  • Database belum siap: jalankan seluruh cms/supabase.sql; periksa URL dan secret key Vercel, kemudian redeploy.
  • Origin ditolak: buka domain yang sama dengan CMS_PUBLIC_URL. Perbaiki nilainya lalu redeploy.
  • RDP OFFLINE: lihat banner Mode CMS pada dashboard lokal. Pastikan agent berjalan, URL production benar dan key cocok.
  • Daftar live kosong: login channel yang benar, pastikan video benar-benar LIVE, lalu Refresh live. Login Google tidak dilakukan di CMS cloud.
  • Agent lain terpasang: jangan menjalankan dua agent. Untuk pindah RDP, pause/putus agent lama dulu. Di SQL Editor jalankan reset pairing di bawah, lalu pair mesin baru.
  • Perintah gagal/kedaluwarsa: perbaiki penyebab dan kirim lagi. Tidak semua perintah bisa menunggu tanpa batas; Stop yang belum diterima kedaluwarsa setelah 2 menit.

update public.ytloop_control
